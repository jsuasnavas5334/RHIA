## Hallazgo real corregido: orden de build roto en el monorepo

`npm run build` (limpio, sin `dist/` previos) falla la primera vez con
`TS2307: Cannot find module '@rhia/opportunity-scoring'` (y
`@rhia/outreach-policy`, `@rhia/secrets`, `@rhia/tool-registry`) en
`messaging`, `next-best-action`, `observability`, `playwright-worker`,
`secrets`, `skill-library`, `threat-model`. Causa real: `npm run build
--workspaces --if-present` procesa los workspaces en orden alfabético,
no en orden de dependencias, y `build:prerequisites` solo cubre 4
paquetes base (`domain`, `config`, `contracts`, `policy`) -- los 17
paquetes nuevos de PH06-PH10 introdujeron dependencias cruzadas
adicionales (p. ej. `tool-registry` → `secrets` → `observability` →
`alerting`; `opportunity-scoring` → `next-best-action`;
`outreach-policy` → `messaging`) que nunca se habían compilado todas
juntas desde una base limpia (el bloqueo de npm lo impidió durante ~24
ciclos). Verificado real: una segunda invocación de `npm run build
--workspaces --if-present` (sin limpiar) termina sin errores, porque los
`dist/` de la primera pasada ya satisfacen las referencias cruzadas --
confirma que es un problema de orden, no un error de código.

**Corrección aplicada (aditiva, reversible, sin tocar esquema/infra):**
`package.json`, script `build`, pasa de una sola pasada a dos
(silenciando la salida de la primera, que puede tener errores de orden
esperados):

```
"build": "npm run build --workspaces --if-present > /dev/null 2>&1; npm run build --workspaces --if-present"
```

Verificado desde limpio (`rm -rf **/dist **/*.tsbuildinfo`): `npm run
build` real termina en ~21s con 0 errores en una sola invocación del
comando. `npm run typecheck` también queda en verde. Alternativa más
robusta a futuro (fuera de alcance de este ciclo): adoptar un
orquestador con grafo de dependencias real (Turborepo/Nx) en vez de
`--workspaces` alfabético; se deja como sugerencia, no como bloqueo.
