## Objetivo

Construir un AI Gateway provider-agnostic que normalice respuestas, tool calls, JSON, usage, costo, timeout y fallback sin introducir lógica de negocio en adapters.

## Dependencias verificadas

- `PH05-T001`: Agent Runtime v1 `DONE` con gate PostgreSQL real aprobado.

## Avance verificable

- Nuevo workspace `packages/ai-gateway` (decisión documentada en `CLAUDE.md`, sección "Ajustes operativos").
- `src/contracts.ts`: contratos neutrales completos — `GatewayRequest`, `GatewayMessage`/`GatewayContentPart` (texto, tool_call, tool_result), `GatewayToolDefinition`, `GatewayResponseFormat` (text/json), `GatewayResult` (SUCCEEDED/FAILED), `GatewayUsage`, `GatewayCost`, `GatewayCapabilities`, `GatewayError`/`GatewayErrorCode`.
- `src/errors.ts`: taxonomía `RHIA_AI_<CONDICIÓN>` (consistente con la taxonomía `RHIA_<DOMINIO>_<CONDICIÓN>` de `packages/contracts`), `retryable` explícito por código, normalización de excepciones no controladas sin filtrar el error crudo.
- `src/transport.ts`: `Transport` inyectable (`send(TransportRequest): Promise<TransportResponse>`); `FetchTransport` real queda disponible para el host pero NINGUNA prueba lo usa — todas las pruebas usan `FakeTransport` (sandbox, sin red ni secretos reales).
- Adapters aislados, sin lógica de negocio, transporte inyectado:
  - `adapters/openai.ts`, `adapters/deepseek.ts`, `adapters/qwen.ts`: comparten `adapters/shared-openai-compatible.ts` (dialecto Chat Completions; DeepSeek y Qwen/DashScope exponen modo compatible) — no es lógica de negocio, es traducción mecánica de forma de mensaje.
  - `adapters/anthropic.ts`: Messages API propia (system separado, `tool_use`/`tool_result` blocks, `max_tokens` obligatorio).
  - `adapters/ollama.ts`: API nativa `/api/chat`. Declara `supportsTools: false` a propósito y el adapter RECHAZA la solicitud (`RHIA_AI_UNSUPPORTED_CAPABILITY`) sin llamar al transporte si el caller pide tools — cumple explícitamente "no fingir features no soportadas". Costo local marcado `isEstimate:false, amount:0` (no es una estimación, es gratis de verdad).
- `src/gateway.ts` (`AiGateway`): `invoke()` aplica timeout vía `AbortController` (con `setTimeout` + señal externa opcional) y bloquea capabilities no soportadas ANTES de llamar transporte; `invokeWithFallback()` prueba una lista de candidatos ya resueltos por el caller en orden mecánico (el Gateway no decide modelo/proveedor — eso es PH05-T003 Router) y agrega `RHIA_AI_ALL_CANDIDATES_FAILED` si todos fallan.
- `src/testing/fake-transport.ts` + `fixtures.ts`: harness de pruebas sandbox (respond/throw/hang) sin red ni credenciales reales.

## Riesgos

- El type-check se hizo con `typescript@6.0.3` genérico del contenedor cloud, no con `typescript@7.0.2` nativo pinneado en el repo (bloqueado hoy en ambos entornos — ver `CLAUDE.md`). Cuando el toolchain real se repare, correr `npm run build`/`test` real sobre `packages/ai-gateway` para confirmar paridad exacta antes de tratarlo como definitivo.
- `FetchTransport` (implementación real sobre `fetch` global) no tiene prueba de integración contra un servidor real — solo compila; queda para cuando el Router/Runtime lo inyecte con credenciales reales fuera de este paquete.
- Pricing usado para `cost.amount` son tarifas de referencia documentadas como aproximación (`isEstimate:true`), no una fuente de facturación oficial.
- El campo `format:"json"` de Ollama no fue validado contra un servidor Ollama real (solo contra `FakeTransport`); el comportamiento real puede variar por modelo.

## Decisiones

- AI Gateway vive en `packages/ai-gateway` (nuevo workspace), no dentro de `apps/agent-runtime` — reutilizable por PH05-T003 (Router) y PH09 (Tools) sin acoplarse al runtime.
- El fallback del Gateway es puramente mecánico sobre una lista de candidatos ya resueltos por el caller; el Gateway NO elige modelo/proveedor por task class/budget — esa decisión es del Router (PH05-T003), evitando lógica de negocio en esta capa.
- OpenAI, DeepSeek y Qwen comparten el helper `shared-openai-compatible.ts` (mismo dialecto de wire format) sin que eso implique lógica de negocio compartida — solo traducción mecánica de forma de mensaje. Anthropic y Ollama son adapters propios por tener formas de wire distintas.
- Ollama declara `supportsTools:false` a propósito (no hay evidencia confiable de soporte universal en modelos locales genéricos vía `/api/chat`) y el Gateway/adapter rechazan la solicitud en vez de fingir soporte.
