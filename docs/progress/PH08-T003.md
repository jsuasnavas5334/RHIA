## Decision de alcance

`packages/messaging` (`@rhia/messaging`), paquete puro, hermano de `outreach-policy`/`channel-gateway`/`sequence-engine`/`evidence-pipeline`. Depende de `@rhia/outreach-policy` (tipo `OutreachChannel`, reusado) y `@rhia/evidence-pipeline` (tipo `Fact`, reusado) -- ambos imports son SOLO DE TIPO (`import type`), confirmados por build real que se eliden en el JS compilado (ningun runtime real de este paquete depende de zod).

**"Sin inventar claims" (criterio central del packet) se resuelve en DOS capas independientes, deliberadamente redundantes:**
1. **Por construccion** (`generate.ts`): el generador es determinista, basado en plantillas (`templates.ts`) con clausulas opcionales que SOLO se incluyen si existe un `Fact` real con ese `predicate` en el `ContextPack` -- nunca hay un LLM de por medio que pueda alucinar (no hay credencial de AI Gateway real autorizada en este ciclo, mismo limite que ya declaro `PH08-T001` para proveedores de canal).
2. **Por auditoria independiente** (`policy-lint.ts`): un guardia separado que NO confia en que el generador se haya comportado bien -- escanea cualquier texto (generado o escrito a mano) buscando claims numericos (empleados/fundacion) sin soporte real en el `ContextPack`, ofertas de precio/descuento, urgencia fabricada, y ausencia de clausula de opt-out.

Esto excede lo minimo que pedia el packet a proposito: incluso si un ciclo futuro reemplaza `generate.ts` por una llamada real a un LLM (AI Gateway, PH05-T002), `policy-lint.ts` sigue siendo el guardia independiente que evita que un claim alucinado por el modelo llegue a un prospecto real.

## Errores que debe evitar (packet) -- como se evitaron

- "Copiar exceso de contenido fuente": el generador nunca inserta texto crudo de ninguna fuente -- `renderFactMention` produce frases cortas propias a partir de un `value` ya estructurado (`{ count, unit }`, `{ year }`, `{ location }}`), nunca el `excerptHash`/texto original de la evidencia (que ademas `@rhia/evidence-pipeline` ya se abstiene de guardar, por su propio criterio "evitar guardar texto entero sin necesidad").
- "Inventar urgencia falsa": ninguna plantilla real usa lenguaje de urgencia fabricada; `policy-lint.ts` (`FALSE_URGENCY`) lo detecta activamente si un mensaje (generado a mano o por un futuro LLM) lo introduce, sin exigir que haya un fact de "deadline" para permitirlo -- v1 es conservador: si hay lenguaje de urgencia, se marca, punto.

## Fuera de alcance de este ciclo (honesto, no oculto)

- **No hay generacion real via LLM/AI Gateway.** `generate.ts` es 100% determinista por plantillas -- no hay ninguna llamada a OpenAI/Anthropic/DeepSeek/Qwen/Ollama (PH05-T002, `@rhia/ai-gateway`, ya DONE pero sin credencial real autorizada en este ciclo). Conectar un LLM real respetando el mismo contrato de salida (`GeneratedMessage`) es trabajo futuro -- probablemente el propio alcance mas amplio de PH08-T004 (Conversation Agent) o una extension de este packet.
- **Solo 3 predicates de Fact tienen mencion real** (`EMPLOYEE_COUNT`/`FOUNDED_YEAR`/`HEADQUARTERS_LOCATION`) porque son los unicos que `@rhia/evidence-pipeline` produce hoy (`DEFAULT_CLAIM_RULES`). Si un ciclo futuro agrega una regla de extraccion nueva a `claim-extraction.ts`, `renderFactMention` debe actualizarse en paralelo (documentado explicitamente en el codigo) o ese predicate nunca se mencionara (fallo seguro: se omite, nunca se inventa un formato).
- **`Inference` no se renderiza todavia en el texto del mensaje** (solo se valida/filtra en `context-pack.ts`). No existe hoy en el repo una taxonomia real de `inferenceType` (el campo existe en la tabla `inference` pero ningun packet cerrado hasta ahora ha definido valores concretos) -- inventar una taxonomia solo para este ciclo habria sido fabricar contexto, no reusarlo. Cuando un packet real (probablemente PH06-T004/PH06-T005, resolucion de entidad, o `next-best-action`) defina `inferenceType`s reales, `generate.ts` puede extenderse con clausulas de inference (siempre con lenguaje de hedge explicito, "estimamos"/"creemos", nunca presentadas como fact).
- **`Inference` es un tipo plano local, no importado de una tabla Drizzle real ni validado con zod** -- ver "Bloqueo de entorno" arriba (zod 4.4.3 real no disponible sin red en este ciclo). Cuando `npm install` corra con red real, vale la pena evaluar si conviene promoverlo a `@rhia/contracts` o a un `schema.ts` propio validado con zod real, replicando el patron exacto de `Fact`.
- **No hay caller real** que conecte `generateMessage`/`lintMessage` con `advanceSequence` de `@rhia/sequence-engine` (PH08-T002, este mismo ciclo) -- `SequenceMessageBuilder` (el punto de extension que `advanceSequence` espera) es una funcion trivial de armar (`(touch, context) => ({ to, subject: generated.subject, body: generated.body, metadata: {...} })`) pero no se escribio en este ciclo para no forzar una dependencia cruzada `messaging -> sequence-engine` sin que el packet de PH08-T003 la pidiera explicitamente.
- **`npm install` no se corrio desde la raiz** (mismo motivo que PH08-T002 -- `device_bash` no disponible). El symlink real de workspace para `@rhia/messaging` no existe todavia en el repo Windows.
