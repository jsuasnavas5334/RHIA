## Qué se construyó

Paquete puro nuevo `packages/research-cache` (`@rhia/research-cache`), hermano de `packages/evidence-pipeline`/`packages/entity-resolver`/`packages/search-orchestrator` — misma decisión de ubicación que PH05-T002/PH06-T002/PH06-T003/PH06-T004 (el packet solo señala "cache/dedupe" como área afectada, sin workspace previo). No persiste nada: recibe evidencia ya cargada por el llamador (mismas `Evidence`/`EvidenceSource` de `@rhia/evidence-pipeline`) y una política de TTL, y devuelve una decisión auditable de si conviene reutilizar esa evidencia o disparar una nueva investigación (mismo patrón de "capa de decisión pura" que `@rhia/entity-resolver`).

- `src/schema.ts`: `CachePolicySchema` (`defaultTtlDays` + overrides opcionales `claimTypeTtlDays`/`sourceTypeTtlDays`, TTL siempre `positive().finite()` — nunca `Infinity`), `ManualInvalidationSchema`, `CacheDecisionSchema` (`CACHE_HIT`/`CACHE_MISS`/`STALE_REVALIDATE`), `CacheDecisionReasonSchema`, `CacheEvaluationResultSchema` (resultado auditable completo).
- `src/cache-key.ts` (acción 1, "Definir cache keys"): `buildCacheKey` — combina `organizationId::subjectType::subjectId::claimType`. `subjectId` es siempre un UUID de entidad ya resuelta (nunca texto libre de nombre de empresa) — misma fórmula que `groupKey` en `fact-collapse.ts` de evidence-pipeline, para que "misma key de cache" y "mismo grupo de evidencia que colapsa a un fact" sean la misma partición.
- `src/ttl-policy.ts` (acción 2, "TTL por claim/source"): `resolveTtlDays` — si hay override por `claimType` y/o `sourceType`, usa el MÁS CORTO de los que apliquen (nunca combinado con el default general); el default solo se usa si ningún override aplica.
- `src/invalidation.ts` (acción 4, "Invalidation"): `findLatestInvalidation` — devuelve la invalidación manual más reciente para una key; evidencia recolectada DESPUÉS de `invalidatedAt` vuelve a ser válida automáticamente (evita que una invalidación bloquee el cache para siempre).
- `src/research-cache.ts` (acción 3, "Reuse evidence" + acción 5, "Record cache hit"): `evaluateResearchCache` — orquestador: filtra evidencia por (organizationId, subjectType, subjectId, claimType), aplica TTL por evidencia `ACTIVE` (considerando su `EvidenceSource.sourceType`), descarta evidencia invalidada manualmente después de su freshness, y devuelve `CacheEvaluationResult` (decision + reason + ttlDaysApplied + evidencia reutilizable/obsoleta trazable) listo para loguear/persistir tal cual.
- `src/index.ts`: barrel export.
