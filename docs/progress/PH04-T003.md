## Objetivo

Construir una app shell navegable para usuarios no técnicos, con estados claros, responsive básico y controles visibles únicamente cuando el rol tenga permiso.

## Dependencias verificadas

- `PH04-T001`: Core API v1 `DONE`.
- `PH04-T002`: Auth v1 y threat checklist `DONE`.

## Avance verificable

- Workspace `@rhia/web` convertido en una aplicación Next.js 16 con React 19 y lockfile reproducible.
- Nueve destinos definidos con permisos de `@rhia/policy`.
- VIEWER recibe solo lectura; OPERATOR no recibe Settings; ADMIN recibe todos los destinos.
- Drawer bajo 768 px y sidebar desde 768 px.
- Estados loading, empty y error incluyen mensajes; empty/error incluyen siguiente acción.
- Dashboard y ocho rutas de módulo se prerenderizan sin depender de n8n.
- Favicon RHIA y metadatos básicos agregados.

## Pruebas y evidencia

- 8/8 component tests aprobaron: permisos por rol, navegación anónima, estado activo y estados de página.
- Typecheck estricto aprobó.
- Build de producción aprobó y generó 12 páginas estáticas, incluido el icono.
- E2E manual en navegador local navegó `Dashboard → Settings → Approvals`, con ambos títulos visibles.
- Vista móvil validada a 390 × 844 px: menú visible, drawer operativo, dos paneles reales y sin overflow horizontal.
- Consola del navegador: cero errores y cero warnings.
- Baseline de repositorio: 22 controles sobre 212 archivos publicables, sin mostrar valores sensibles.

## Decisiones

- La navegación visible se deriva de `@rhia/policy`; la API continúa siendo la autoridad final.
- Desarrollo usa un ADMIN de demostración definido únicamente en servidor para permitir revisión visual local.
- Producción falla cerrada con cero roles hasta conectar la sesión Better Auth; nunca acepta roles desde cliente, URL o Web Storage.
- Dependencias exactas fijadas con npm 11.17.0, sin introducir otro package manager.

## Riesgos

- La UI no debe usar ocultamiento visual como sustituto de autorización server-side.
- La conexión del `Principal` Better Auth al layout productivo queda como integración pendiente antes de deployment.
- Las secciones son placeholders deliberados; Operations Center corresponde a `PH04-T004`.
