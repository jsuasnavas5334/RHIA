## Fuera de alcance de este ciclo (honesto, no oculto)

- **No hay ningun proveedor real de calendario conectado.** `CalendarAdapter` es un puerto tipado -- conectar Google Calendar/Microsoft Graph reales (con credenciales reales autorizadas) es wiring de infraestructura futuro, mismo limite que `channel-gateway`/`ai-gateway` ya declararon para sus proveedores.
- **El conflicto de double booking se detecta por `contactId`, no por `organizerRef`.** La tabla real `meeting` no guarda quien es el organizador humano/agente -- si un ciclo futuro necesita detectar que UN MISMO organizador tiene dos reuniones superpuestas con contactos DISTINTOS, eso requeriria agregar esa columna a la tabla real (decision de esquema fuera de alcance de este ciclo, no tomada unilateralmente aqui).
- **La duracion de un meeting (30 min por defecto) es un supuesto de calculo, no un campo persistido.** La tabla real `meeting` no guarda una duracion -- `DEFAULT_MEETING_DURATION_MINUTES` se usa SOLO para el chequeo de superposicion de horarios en memoria, nunca se escribe en ningun registro real.
- **No hay caller real** que conecte este motor con `apps/core-api` (crear un Job/registrar el meeting en Postgres real) ni con el Operations Center (PH04-T004) para mostrar el dashboard KPI a un humano -- mismo limite que todos los hermanos de PH08.
- **`npm install` no se corrio desde la raiz** (mismo motivo, `device_bash` no disponible) -- el symlink `node_modules/@rhia/meeting-scheduler` no existe todavia en el toolchain real de Windows.
