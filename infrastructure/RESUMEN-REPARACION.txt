PROBLEMA IDENTIFICADO / PROBLEM IDENTIFIED:
───────────────────────────────────────────────────────────────────────────────
N8N mostraba "ERR_EMPTY_RESPONSE" en localhost:5679 porque el contenedor N8N
estaba fallando con el error:
  "password authentication failed for user "n8n"

Causa Raíz / Root Cause:
- PostgreSQL fue inicializado sin crear el usuario "n8n" 
- N8N intentaba conectarse usando credenciales de "n8n" que no existían
- Los contenedores se reiniciaban repetidamente sin poder conectar a la base de datos


SOLUCIÓN APLICADA / SOLUTION APPLIED:
───────────────────────────────────────────────────────────────────────────────
Se implementó una estrategia de 3 pasos:

[1] Crear Script de Inicialización de PostgreSQL
    - Archivo: init-n8n-user.sql
    - Crea usuario "n8n" con contraseña
    - Crea base de datos "n8n" propiedad del usuario
    - Asigna todos los permisos necesarios

[2] Actualizar docker-compose.yml
    - Agregar volumen: ./init-n8n-user.sql:/docker-entrypoint-initdb.d/01-init-n8n.sql:ro
    - PostgreSQL ejecutará este script automáticamente al inicializar la DB

[3] Ejecutar Secuencia de Reparación
    - Detener todos los contenedores
    - Eliminar volumen PostgreSQL antiguo para reinicializar
    - Reiniciar contenedores
    - PostgreSQL ejecuta init-n8n-user.sql automáticamente
    - N8N puede ahora autenticarse correctamente
